# AI Software Architect specification

## Current implementation boundary

The production implementation is one Go system. internal/architect is the only contract authority and owns schema version 1.1.0, strict YAML decoding, ADR and bundle validation, generated JSON Schemas, workspace/path safety, dependency and boundary analysis, artifact guarding, rendering, and bounded repository snapshots. internal/codex is the Codex control plane.

Python examples in bundled pattern references and development-only evaluation records are content, not runtime dependencies. Historical evaluation ledgers and release evidence remain opaque append-only records.

## Contract

Production validators accept exactly schema_version 1.1.0. Unknown YAML fields, aliases, duplicate mapping keys, malformed nested objects, invalid identifiers, invalid cross-references, and excessive nesting are rejected. The checked-in schemas are generated by:

    go run ./cmd/generate-schemas

The CI contract is:

    go run ./cmd/generate-schemas --check

Contracts contain scope, quality attributes, components, external boundaries, dependency rules, required and prohibited practices, decision identifiers, and unresolved questions. Decisions use ADR-NNN identifiers and reference the exact considered and selected options.

## Workflow and safety

The architecture workflow is explicitly activated by the structured plugin selection or the $ai-software-architect marker. Natural-language mentions alone do not activate it. The control plane keeps typed continuation and checkpoint state with bounded lifetimes and one-shot consumption.

All five Codex events are implemented in Go:

- UserPromptSubmit routes activation, continuation, bundled references, and the bounded snapshot command.
- PreToolUse denies web lookup, unsafe shell composition, application-code writes, secrets, invalid contracts, invalid ADRs, and incomplete approved bundles.
- PostToolUse verifies persisted artifact bytes and records a complete validated bundle.
- PostCompact restores only the typed workflow checkpoint.
- Stop validates stable visible response structures, persists a pending clarification or decision, and blocks malformed responses.

The runtime fails closed on malformed input, missing state, invalid event names, missing workspace roots, reconstruction failures, and post-write mismatches. It never executes repository code or starts a persistent server.

## Native distribution

The only runtime invocations are:

    --codex-hook --event UserPromptSubmit
    --codex-hook --event PreToolUse
    --codex-hook --event PostToolUse
    --codex-hook --event PostCompact
    --codex-hook --event Stop
    --repository-snapshot --root .

The release matrix builds windows/amd64, darwin/arm64, linux/amd64, and linux/arm64. VERSION is the sole release version source and is injected into binaries and manifests. Packages contain native binaries and bundled skills only; Python, uv, PyInstaller, project dependencies, and network downloads are not required.

Linux binaries are cross-compiled and smoke-tested on native Linux. Linux Codex host lifecycle support is not claimed until separately verified. Windows reparse-point, macOS path, and Linux filesystem tests remain part of the platform validation gates.

## Verification

The required gates are:

    go test ./...
    go test -race ./...
    go vet ./...
    make build-all
    make smoke-linux

Package extraction must pass cmd/codex-plugin validation and contain exactly one target runtime. Exploratory evaluation must confirm clarification, approval persistence, static inspection, artifact safety, source immutability, compaction restoration, post-write verification, and fail-closed behavior.
