# M-16 retrieval benchmark

The M-16 gate keeps Markdown, YAML, and JSON as the canonical architecture
source and evaluates a disposable SQLite FTS5 projection before considering
sqlite-vec. The benchmark is maintainer-only evidence; it is not part of the
project runtime or the Codex hook path.

## Run the gate

From the repository root, run:

```sh
uv run python scripts/benchmark_retrieval.py --iterations 25
```

The command reads the versioned fixture at
`tests/fixtures/retrieval/m16.json` and writes the generated report to
`.tmp/retrieval/m16-report.json`. The report contains the fixture hash, backend
configuration, raw query results, and all aggregate measurements. It must be
regenerated by the command rather than edited by hand.

SQLite FTS5 is a prerequisite for the gate. Hosts without the SQLite FTS5
extension fail the command explicitly; they do not silently substitute a
different ranking implementation.

## Evidence recorded

The fixture contains eight project questions over thirteen ADR-like documents.
Each question declares relevant documents and answer-support terms. Both a
deterministic JSON lexical scan and SQLite FTS5 are measured so the report has
a simple reference backend.

For each backend and cutoff, the report records:

- precision, recall, MRR, and nDCG;
- answer-support term coverage;
- p50 and p95 query latency, with the complete sample count;
- full-corpus token count, returned top-k token count, and context reduction;
- per-query ranked results for inspection.

The lifecycle section rebuilds the index from the same documents in normal and
reversed input order, checks document IDs and content digests, replaces one
canonical document and verifies that the old body disappears, then corrupts
the derived database and verifies detection followed by a clean rebuild.

The fixture is deterministic and intentionally small, so its latency numbers
are descriptive rather than production capacity targets. Ranking metrics are
the decision evidence for this corpus; a future vector comparison must use the
same questions, relevance labels, support terms, and reporting fields.

## Decision gate

The current implementation selects SQLite FTS5 as the local keyword baseline and
does not add sqlite-vec or an embedding dependency. sqlite-vec may be considered
only after a representative corpus shows a material ranking improvement over
this baseline and separately accounts for dependency availability, rebuilds,
backup/restore, stale data, and cross-platform packaging.
